# OpenCode Smart Context — помощник контекста

[English](README.md) · Русский

Плагин даёт модели два способа управлять контекстом: **сократить историю и продолжить текущую работу** или **открыть отдельный чат для другой темы**. Модель видит расход контекста и сама выбирает подходящий момент.

## Два режима

### 1. Продолжить работу в том же чате с коротким контекстом

Это аналог встроенного сокращения контекста — compaction в OpenCode/Codex. Чат и задача остаются прежними, но вместо всей накопленной переписки модель получает сохранённое состояние работы и последующие сообщения. Старая переписка остаётся доступной в истории.

Здесь решение о сокращении принимает сама основная модель: она учитывает свободное место и то, что предстоит делать дальше. Она сохраняет `HANDOFF.md` — файл с задачей, решениями, ограничениями, результатами проверок и следующим шагом. Плагин фиксирует снимок и выполняет переход после завершения текущих действий. Отдельная модель для суммаризации не вызывается.

### 2. Открыть новый чат для другой темы

Если в длинном разговоре начинается другая тема, модель может предложить отдельный чат. После вашего согласия плагин создаёт его с новым названием и передаёт только сведения, нужные новой теме.

Это другой разговор, а не очередной этап прежнего: обсуждение нового вопроса не тащит за собой старую переписку. Прежний чат сохраняется, к нему можно вернуться; темы проще найти отдельно.

## Почему появился плагин

В длинных сессиях с GPT-6.1 создатель замечал более долгие размышления, залипание и уход от задачи примерно после трети контекста. Поэтому здесь используется рабочий ориентир около 28%. Цель — держать модель в той части окна, где она работает продуктивнее, а не ждать заполнения технического предела.

Обычное автоматическое сокращение вызывало недоверие: непонятно, почему оно случилось именно сейчас и какие детали сохранились. Приходилось вручную создавать новые чаты. Особенно беспокоил сценарий, когда около 25% начинается большая работа с несколькими циклами изменений и проверок, а потом модель уже хуже работает и не может подготовить хорошую передачу.

Поэтому плагин показывает модели запас, но не переключает её по проценту или таймеру. Модель может подготовить передачу до большого этапа или после законченного небольшого шага.

## Передачу можно проверить по ходу работы

Модель ведёт HANDOFF во время работы, а вы читаете небольшие изменения файла рядом с её ответами. Ошибку или пропущенное решение можно поправить сразу. Перед переходом остаётся актуализировать уже проверенное состояние, а не вспоминать всю сессию и проверять длинную суммаризацию с нуля.

## Когда полезен

- GPT-6.1 Sol или GPT Astra дольше думает, залипает или теряет инструкции в длинном чате.
- После автоматической суммаризации теряются важные детали.
- Приходится самому переносить задачу в новый чат.
- Разные темы накапливаются в одном разговоре и их неудобно искать.

В ежедневной работе создателя такой подход заметно уменьшил залипание и сделал долгую работу существенно комфортнее. Это помощь через управление контекстом; постановка задач и правила согласования по-прежнему нужны.

## Использование

Откройте `/continuity`, чтобы включить или выключить помощника, посмотреть расход контекста и историю передач. По умолчанию он включён.

Переходы модель выполняет через `context_handoff`. `resume=true` автоматически продолжает порученную работу; `resume=false` сохраняет продолжение без запуска модели и ждёт вашего сообщения. Этот вариант также позволяет выбрать другую модель через `/models`.

[Инструкции плагина](CONTEXT-CONTINUITY-PROMPT.md) описывают работу с контекстом. Обычные инструкции агента и правила проекта продолжают действовать; личные правила из среды создателя в плагин не входят.

## Что получает модель

При включённом плагине в каждый обычный запрос добавляются:

- Текст [CONTEXT-CONTINUITY-PROMPT.md](CONTEXT-CONTINUITY-PROMPT.md): беспокойства, выбор момента перехода и правило вести состояние каждого проекта. Если файл состояния ещё не создан, модель должна создать `HANDOFF.md` в корне.
- Описание инструмента `context_handoff` из [index.ts](index.ts).
- Текущие показатели и оценки запаса, формируемые в [core.ts](core.ts).

Это вариант инструкций, с которым создателю удобно работать. Файл `CONTEXT-CONTINUITY-PROMPT.md` можно отредактировать под себя; после изменения перезапустите OpenCode. Сохраните заголовок `## Working conditions`: загрузчик использует его как начало инструкции.

Состояние вашей работы — отдельный проектный HANDOFF. При сокращении текущего чата его снимок подставляется вместо старой истории; в другой чат передаётся только подготовленное моделью поручение для новой темы.

## Установка

Локальная версия `0.1.0`. Сервер проверен: **OpenCode V1 1.18.35, Linux**. V2 не проверена.

<details>
<summary>Локальное подключение и настройки</summary>

Склонируйте полный каталог исходников вне автоматически загружаемых каталогов `plugins/` OpenCode и установите закреплённые зависимости:

```sh
git clone https://github.com/roboroddom/opencode-smart-context.git
cd opencode-smart-context
bun install --frozen-lockfile
```

`~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["/ABSOLUTE/PATH/opencode-smart-context/index.ts"],
  "compaction": { "auto": false, "prune": false }
}
```

`~/.config/opencode/tui.json`:

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["/ABSOLUTE/PATH/opencode-smart-context/tui.tsx"]
}
```

Замените пути, сохраните существующие настройки/записи плагинов и перезапустите OpenCode. При заданном `XDG_CONFIG_HOME` используйте `$XDG_CONFIG_HOME/opencode/`.

Состояние: `~/.local/share/opencode-context-continuity/` либо `$XDG_DATA_HOME/opencode-context-continuity/`. `OPENCODE_CONTINUITY_STATE_DIR` заменяет этот путь; сервер и панель должны использовать один.

Для удаления: сохраните HANDOFF, дождитесь завершения переходов, уберите обе записи подключения, восстановите прежние настройки сокращения и перезапустите. Продолжите в новой сессии из HANDOFF: без плагина старая история больше не отсекается. Переключатель сохраняет установленные границы.

Если `/undo` удалил границу, по возможности используйте `/redo` либо начните новую сессию из HANDOFF. Не удаляйте состояние для её починки.

</details>

**Сервер отключает штатное автоматическое сокращение и удаление старых результатов инструментов во всём экземпляре, даже при выключенном помощнике. Пропущенный переход может привести к переполнению контекста.** Ориентир 28% взят из опыта создателя, а не является автоматическим сигналом перехода.

## Рабочий эксперимент

Это вайбкод-эксперимент и предложение работать таким способом, а не законченная система управления агентом. Он уже работает и, по опыту создателя, делает обычный чат со стандартными суммаризациями существенно комфортнее.

Если тема интересна, попросите своего агента изучить код и попробуйте адаптировать подход: свои инструкции, промпты и правила переходов.

Дальше исследуется более эффективная сборка входа каждого шага: переиспользование правильно собранного кешируемого префикса, чтобы меньше платить за ввод там, где провайдер поддерживает кеш. Другие направления — HANDOFF по темам, кратковременная и долговременная память, более управляемая работа агента. Пока это открытые вопросы, не готовые возможности плагина.
